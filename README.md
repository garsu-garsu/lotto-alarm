## ✨ 핵심 기능

## 📐 번호 추천 — 근거 있는 것만 남겼습니다

빈도 가중 같은 흔한 방식은 균등 대비 15% 안쪽 차이라 **사실상 랜덤**이었습니다. 그래서 1,235개 회차에서
`인기도 지수 = 1등 당첨자 수 ÷ 기대 당첨자 수`(기대 당첨자 = 매출÷1000 ÷ 8,145,060)를 계산해 검정하고,
**통과한 것만** 전략에 넣었습니다.

| 특성 | 결과 | Welch t |
|---|---|---|
| 합계 ≥160 | 1등 당첨자 **0.88배** (합계 ≤117 은 1.01배) | 3.53 |
| 연속수 포함 | **0.93배** (없으면 1.01배) | −3.11 |

떨어진 것은 전부 뺐습니다 — 생일 조합(t=1.48) · 끝자리 중복(1.47) · 직전회차 겹침(−1.26) · 홀수 3개(0.64) · 5의 배수(−1.44) · 범위 35+(0.65).

| 방식 | 제약 | 실제 효과 |
|---|---|---|
| 완전 무작위 | 없음 | 기준선. 모든 조합 1/8,145,060 |
| **덜 붐비는 조합** | 합계 ≥160 + 연속쌍 | 확률은 그대로, **나눠 갖는 인원이 적음** |
| 가장 흔한 모양 | 홀수 3개 + 합계 121~160 | **확률 안 오름** (화면에 명시) |
| 겹치지 않게 분산 | 5게임 서로소 | 5등 이상 하나라도 **12.42% vs 11.06%** (40만 회 시뮬레이션) |

> 어느 방식도 당첨 확률을 높이지 못한다는 고지를 화면 상단에 고정으로 띄웁니다. 예측·적중 보장 표현은 쓰지 않았습니다.

**푸시 문구 규칙** — 콘솔 AI 검수가 세 가지를 봅니다. 문구를 고칠 때 걸립니다.

## 용지 QR 읽기

앱인토스 SDK에는 QR 스캐너가 없습니다. 그래서 **실시간 스캔이 아니라 사진 한 장을 찍어 해독**합니다.

`Device.openCamera({ base64: true, maxWidth: 2048 })` (또는 `Device.getPhotos` 로 찍어둔 사진 선택)
→ canvas 로 픽셀을 읽어 `jsqr` 로 해독 → 아래 형식을 파싱 → 번호 자동 저장 + 그 회차로 즉시 등수 판정.

로또 용지 QR이 담고 있는 값:

```
https://m.dhlottery.co.kr/qr.do?method=winQr&v=1195m060713162425m050912202126m…0000000645.net
                                                ^^^^ 회차   ^^^^^^^^^^^^ 게임 1개(6개×2자리)
```

`v=` 뒤 앞 4자리가 회차, 이어서 `[영문자][숫자 12자리]`가 게임 수(최대 5)만큼 반복되고 뒤에 시리얼이 붙습니다.
구분 문자는 선택 방식에 따라 `m`/`q` 등으로 달라져서 글자에 의존하지 않고 `[A-Za-z]\d{12}` 로 매칭합니다.

읽기 실패하면 직접 입력으로 안내합니다. 확대 재시도는 iOS 캔버스 픽셀 상한(약 1,670만) 안에서만 합니다 —
넘기면 캔버스가 통째로 비어서 오히려 못 읽어요.

## 당첨번호 데이터

동행복권 공식 JSON API(`getLottoNumber`)가 현재 홈으로 302 리다이렉트해서 쓸 수 없습니다.
대신 CORS가 열린 공개 미러(`smok95.github.io/lotto`)를 씁니다 — 백엔드 0개.

**미러가 갱신을 멈추면 이 앱의 당첨번호도 멈춥니다.** 공식 API가 복구되거나 data.go.kr 키를
발급받으면 `src/lib/lotto.ts` 의 `BASE` 만 바꾸면 됩니다.

## 개발

```bash
npm install
npm run dev          # 브라우저 (광고·알림은 미지원 환경으로 자동 우회)
npm run check:lotto  # 등수 판정 · 추첨시각 계산 · 번호추천 자체 점검
npm run typecheck
npm run build        # vite build + ait build → lotto-alarm.ait
npm run deploy
```

`.env.example` 를 `.env` 로 복사하고 앱인토스 콘솔에서 발급받은 광고그룹 ID를 채우세요.
비워두면 배너는 그려지지 않고 리워드 광고는 즉시 통과해서, 브라우저 개발이 끊기지 않습니다.
