# 🎯 로또 알람 (lotto-alarm)

**이번 주 당첨번호를 바로 보여주고, 사는 것도 확인하는 것도 대신 알려주는 앱**

## 무엇을 하는 앱인가

| | |
|---|---|
| **당첨번호** | 이번 주 회차 번호 6개 + 보너스, 등수별 당첨금, 다음 추첨까지 남은 시간 |
| **내 번호 확인** | 산 번호를 저장해 두면 발표 직후 몇 등인지 자동으로 대조 |
| **번호 추천** | 리워드 광고를 보면 추천 5게임 생성 (과거 출현 빈도 기반) |
| **알림** | "로또 사세요" / "번호 확인하세요" 를 원하는 시각에 받기 |

## 알림 시각과 방해금지

앱인토스 푸시는 **야간 방해금지**가 걸려 있어 21시 이후로는 발송되지 않습니다.
그래서 슬롯을 전부 그 안쪽으로 잡았습니다.

**구매 알림** — 추첨(토 20:45) 전에 아직 살 시간이 남아 있는 시각만

| 발송 코드 | 시각 |
|---|---|
| `lotto-alarm-buy-fri1900` | 금요일 저녁 7시 |
| `lotto-alarm-buy-sat1000` | 토요일 오전 10시 |
| `lotto-alarm-buy-sat1400` | 토요일 오후 2시 |
| `lotto-alarm-buy-sat1800` | 토요일 오후 6시 |

**확인 알림** — 발표 직후(21시 컷 직전) 또는 다음 날 아침

| 발송 코드 | 시각 |
|---|---|
| `lotto-alarm-check-sat2050` | 토요일 밤 8시 50분 |
| `lotto-alarm-check-sun0800` | 일요일 오전 8시 |
| `lotto-alarm-check-sun1000` | 일요일 오전 10시 |

> 앱은 **동의만 받습니다.** 실제 발송은 앱인토스 콘솔의 스마트 발송에서 위 코드로 예약해야 동작해요.
> 코드를 바꾸면 콘솔의 발송 코드도 같이 바꿔야 동의 화면이 뜹니다.

## 광고

| 자리 | 형태 | 갱신 |
|---|---|---|
| 화면 하단 고정 (앱 전체 1개) | 문구 강조형 배너 | 30초 |
| 각 화면 본문 맨 아래 | 이미지 강조형 배너 | 30초 |
| 번호 추천 버튼 | 리워드(전면) 광고 | — |

30초인 이유: 토스 배너는 AdMob 기반이고, AdMob은 30초보다 잦은 갱신을 무효 트래픽으로 봅니다.
화면이 가려져 있는 동안(`visibilitychange`)에는 갱신을 멈춰 헛호출을 만들지 않습니다.

## 당첨번호 데이터

동행복권 공식 JSON API(`getLottoNumber`)가 현재 홈으로 302 리다이렉트해서 쓸 수 없습니다.
대신 CORS가 열린 공개 미러(`smok95.github.io/lotto`)를 씁니다 — 백엔드 0개.

**미러가 갱신을 멈추면 이 앱의 당첨번호도 멈춥니다.** 공식 API가 복구되거나 data.go.kr 키를
발급받으면 `src/lib/lotto.ts` 의 `BASE` 만 바꾸면 됩니다.

## 개발

```bash
npm install
npm run dev          # 브라우저 (광고·알림은 미지원 환경으로 자동 우회)
npm run check:lotto  # 등수 판정 · 추첨시각 계산 · 번호추천 자체 점검
npm run typecheck
npm run build        # vite build + ait build → lotto-alarm.ait
npm run deploy
```

`.env.example` 를 `.env` 로 복사하고 앱인토스 콘솔에서 발급받은 광고그룹 ID를 채우세요.
비워두면 배너는 그려지지 않고 리워드 광고는 즉시 통과해서, 브라우저 개발이 끊기지 않습니다.

## 기술 스택

TypeScript 5.7 (strict) · React 18 · Vite 6 · TDS Mobile · `@apps-in-toss/web-framework` 3.0.2
상태는 localStorage 만 씁니다. 서버 없음.
